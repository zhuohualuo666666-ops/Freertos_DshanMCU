<!-- 任务通知的本质 -->

### 
AB任务使用队列、信号量、事件组通信需要创建对应的结构体，两个任务通过结构体这个中间对象实现通信；
使用任务通知A可以直接修改B中的值；
每个任务都有自己的TCB结构体：
typedef struct tskTaskControlBlock
{
......
/* configTASK_NOTIFICATION_ARRAY_ENTRIES = 1 */
volatile uint32_t ulNotifiedValue[ configTASK_NOTIFICATION_ARRAY_ENTRIES ];
volatile uint8_t ucNotifyState[ configTASK_NOTIFICATION_ARRAY_ENTRIES ];
......
} tskTCB

其中ucNotifyState（通知状态）有三种取值：
taskNOT_WAITING_NOTIFICATION：任务没有在等待通知
taskWAITING_NOTIFICATION：任务在等待通知
taskNOTIFICATION_RECEIVED：任务接收到了通知

###
B任务TCB结构体中通知状态初始值为taskNOT_WAITING_NOTIFICATION（没有在等待通知），
B可以调用函数将自己状态改为taskWAITING_NOTIFICATION（任务在等待通知），
当A将通知发给B，B的通知状态值被A改为taskNOTIFICATION_RECEIVED（任务接收到了通知）；

B只有因为状态为taskWAITING_NOTIFICATION（任务在等待通知）而阻塞才能被任务通知唤醒，且状态变为taskNOTIFICATION_RECEIVED（任务接收到了通知），退出取出通知函数时内核会将状态重置为taskNOT_WAITING_NOTIFICATION（没有在等待通知）；
如果因为其他原因阻塞收到通知并不能被唤醒，但当B结束其他原因导致的阻塞后，调用取出通知函数时发现状态已经变为taskNOTIFICATION_RECEIVED（任务接收到了通知），取出通知函数立即返回，B不进入阻塞

###
任务通知有两套函数，简化版与专业版：
一.简化版：
BaseType_t xTaskNotifyGive( TaskHandle_t xTaskToNotify )：发出通知
uint32_t ulTaskNotifyTake( BaseType_t xClearCountOnExit, TickType_t xTicksToWait )：取出通知

在简化版中，B的TCB结构体中的ulNotifiedValue（通知值）会根据xClearCountOnExit的值的不同pdfalse或pdtrue而被当做一个二值信号量或计数信号量,
A调用xTaskNotifyGive函数会使ulNotifiedValue（通知值）加1，
如果B因调用ulTaskNotifyTake而处于阻塞状态，B被唤醒且ucNotifyState（通知状态）改为taskNOTIFICATION_RECEIVED（任务接收到了通知），ulNotifiedValue（通知值）根据xClearCountOnExit配置清0或减1，
如果B因其他原因处于阻塞状态，B的ucNotifyState（通知状态）改为taskNOTIFICATION_RECEIVED（任务接收到了通知），但不被唤醒
ulTaskNotifyTake函数返回值为退出（清0或减1）前的ulNotifiedValue（通知值）的值

二.专业版：
·BaseType_t xTaskNotify( TaskHandle_t xTaskToNotify, uint32_t ulValue, eNotifyAction eAction )：发出通知

xTaskNotify参数依次为通知对象，通知值，通知值的用法；
eAction取值如下：
1.eNoAction：将ucNotifyState（通知状态）改为taskNOTIFICATION_RECEIVED（任务接收到了通知），不修改ulNotifiedValue（通知值）
2.eSetBits：修改ulNotifiedValue（通知值）某一个bit
3.eIncrement：ulNotifiedValue（通知值）加1
4.eSetValueWithoutOverwrite（不覆盖）：当ucNotifyState（通知状态）为taskNOTIFICATION_RECEIVED（任务接收到了通知），不修改ulNotifiedValue（通知值）；当ucNotifyState（通知状态）不是taskNOTIFICATION_RECEIVED（任务接收到了通知），更新ulNotifiedValue（通知值）为ulValue
5.eSetValueWithOverwrite（覆盖）：无论ucNotifyState（通知状态）是什么，更新ulNotifiedValue（通知值）为ulValue

·BaseType_t xTaskNotifyWait( uint32_t ulBitsToClearOnEntry,
uint32_t ulBitsToClearOnExit,
uint32_t *pulNotificationValue,
TickType_t xTicksToWait )

xTaskNotifyWait参数：
1.ulBitsToClearOnEntry：入口处非taskNOTIFICATION_RECEIVED（任务接收到了通知）状态时清除ulNotifiedValue（通知值）的哪些bit
2.ulBitsToClearOnExit：为taskNOTIFICATION_RECEIVED（任务接收到了通知）状态时清除ulNotifiedValue（通知值）的哪些bit
3.pulNotificationValue：收到通知后用来保存原本未经修改的通知值
4.xTicksToWait：超时时间

简单说，这个函数作用：收到通知前清除ulBitsToClearOnEntry参数的通知值bit，收到通知后清除ulBitsToClearOnExit参数的通知值bit，返回值为pulNotificationValue
