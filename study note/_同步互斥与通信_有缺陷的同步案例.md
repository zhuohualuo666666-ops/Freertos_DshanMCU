案例：

static int g_LCDCanUse = 1;
static volatile int g_calc_end = 0;
static uint64_t g_time = 0;
static uint32_t g_sum = 0;

void CalcTask(void *params)
{
	uint32_t i = 0;
	
	LCD_PrintString(0, 0, "Waiting");

	g_time = system_get_ns();
	for (i = 0; i < 10000000; i++)
	{
		g_sum += i;
	}
	g_calc_end = 1;
	g_time = system_get_ns() - g_time;

	vTaskDelete(NULL);
}


void LcdPrintTask(void *params)
{
	int len;
	while (1)
	{
		LCD_PrintString(0, 0, "Waiting");
		
		vTaskDelay(3000);
		
		while (g_calc_end == 0);
		
		/* 打印信息 */
		if (g_LCDCanUse)
		{
			g_LCDCanUse = 0;
			
			LCD_ClearLine(0, 0);
			len = LCD_PrintString(0, 0, "Sum: ");
			LCD_PrintHex(len, 0, g_sum, 1);
			
			LCD_ClearLine(0, 2);
			len = LCD_PrintString(0, 2, "Time(ms): ");
			LCD_PrintSignedVal(len, 2, g_time/1000000);
			
			g_LCDCanUse = 1;
		}
		vTaskDelete(NULL);
	}
}

以上是freertos创建的两个任务，优先级相同，案例对比了LcdPrintTask函数中
加和不加vTaskDelay(3000);这一句的区别，不加这一句打印出的时间大约2500ms，
加上这一句打印出的时间大约1200ms，缩短了一半，
原因是原本两个任务交替运行，在CalcTask任务运行完之前，LcdPrintTask任务永远不可能跳出while (g_calc_end == 0);这一句，
而vTaskDelay(3000);这一句将LcdPrintTask任务变为了阻塞态，让CalcTask任务单独运行且能够执行完，因此缩短了一半的时间。
这是一种使用全局变量的方式来同步的方法，该方法不完善，效率不高，可以考虑使用唤醒的的方式，CalcTask执行完后唤醒LcdPrintTask。


这个案例一开始程序未正常运行，卡死在while (g_calc_end == 0);这一句，
打开调试端口发现汇编码里程序一直在CMP和BEQ两步之间循环，LDR没有包含进去，
给出的结论是编译器优化问题，
g_calc_end变量在其他函数中被修改，而本函数中只在一开始读取该变量的值存入寄存器，后续一是从寄存器中读这个值，
因此读的一直是原始值，导致程序卡死，加上volatile关键字即可。
